# Phase 3c 实施计划：提取预算修复 + 词法下限 + decay（flag 门控）

> 依据：Phase 3a 统计基线（dedup 20%，量化后第一缺口）与 3b 库深归因
> （noise 残留 = BM25 词法通道）。基线 `930b628`。

## 1. 根因（dedup 20% 的真凶，与 R-012 假设不同）

隔离复现 + audit 链证明：dedup 失败**不是** AUDN 决策不稳定——
真模型探针 15/15 全对（改述 NOOP ×12、换值 UPDATE，温度下完全确定）。
真凶是 **MEMORY_EXTRACTION_TIMEOUT 级联**：

- 提取预算默认 2s（生产）/ 12s（评测），few-shot 后的 DeepSeek 提取
  经常超过它；
- 一条慢提取耗尽整个 drain 的预算 → 同批其他事件连带超时 → 目标事实
  根本没建出来 → 改述候选找不到可匹配的记忆 → 相似度 0 → ADD →
  「断言增长」被记为 dedup 失败。

修复：预算默认提到 30s（drain 是异步后台任务，不影响用户回合延迟）。

## 2. 词法相对下限（3b 归因的直接修复）

BM25 分数无上界，绝对阈值不可行；改为**相对下限**：低于词法通道最高分
30%（`MEMORY_LEXICAL_FLOOR_RATIO`）的长尾二元巧合在融合前丢弃。
默认 0.3 上生产；0 保持旧行为。

## 3. decay 重排（flag 门控，默认关）

- 实现：融合后按断言 updatedAt 做 14 天半衰期、权重 0.3 的 recency
  乘权重排（`MEMORY_DECAY_REWEIGHT`）；
- **默认关的理由**：3b 实测排序质量随库深零衰减（needle hit@1=100%
  @2000），decay 在当前数据下无收益空间；且系统没有按记忆的访问时间
  追踪，只有 updatedAt——等访问追踪落地后再评估开启。

## 4. 诚实负结果：AUDN 相似度短路被校准否决

原计划「cos ≥ 0.88 直接 NOOP 跳过模型」。校准（本地 bge-m3）：

| 对 | cos |
|---|---|
| 改述（A-D01 对） | 0.9193 |
| 改述（A-D12 对） | 0.9002 |
| **换值（榴莲→西瓜）** | **0.9092** |
| 严重度 UPDATE（B-15 对） | 0.7835 |
| 无关 | 0.4365 |

换值的相似度**高于部分改述**——相似度阈值无法区分两者，短路会静默
丢失换值更新（正是 R-011 事实级 key 要保护的场景）。方案放弃。

## 7. E-3 结果（2026-09-08，n=2/3）

### 7.0 两次假绿的教训（写入流程）

E-3 做了三轮才拿到有效数据，前两轮都被静默降级骗过：

1. 第一轮 15s 假绿：finally 里 `process.exit(0)` 吞异常 + shell USER 为空
   导致 PG 连接失败被包装成"0 失败"。修复：catch 打印 abortReason +
   非零退出；连接串显式解析 PG 用户（`070a735`）。
2. 第二轮 5 次跑（3 连跑 + 2 对照）全部在 Ollama 死亡（重启未自启）的
   纯词法退化模式下测量：paraphrase"回归"6.7pp、dedup"无改善"、
   floor/budget 两对照全持平——共享依赖（embedding 端点）死亡时所有
   对照一起失效。修复：embedding preflight，端点死直接 exit 2（`9268149`）。

### 8.1 dedup 95% 的唯一顽固 case

三次运行各挂一个不同 case（D12/D18/D14）——单发提取方差，非系统性。
dedup 从 20% → 95% 的提升与 15/15 审计探针、隔漓复现互相印证。

### 8.2 precision_noise 82.7% 是指标缺陷而非回归

判据是 `retrieved.length > 0` 即 fail（零容忍）。提取修复让语料从
"提取饥饿"（3a 只有少量断言、词表贫乏、噪声查询撞不到词）变为健康
语料——无关查询开始能撞到词，于是零容忍判据大面积触发。失败明细里
BM25 独通模式（分数 3-10）与 RRF 模式（分数 0.016）混杂。**"检索到
东西"≠"会呈现给用户"**（下游有 compaction/过滤）。该指标需改为分数
阈值或 answerability 判定，否则它惩罚的恰恰是提取修复的成功。

### 8.3 arbitration 71.1% 的三类机制（定向探针归因）

审计探针（scripts/audn-arbitration-probe.js）：15/15 换值→UPDATE、
3/3 改述→NOOP，带 5 个干扰项仍全对——**审计器无罪**。隔离复现
（scripts/arbitration-repro.js）：单对换值在干净语料下 100% 落库。
真实机制：

1. **关键词形式不匹配（永久失败，与模型无关）**：C-A09 候选写
   "Gmail"（大写），判据 `includes('gmail')` 大小写敏感；C-A01 候选
   "可以正常食用花生"，判据找 "能吃"。改写合理但字面不命中。
2. **无上下文提取的指代消解缺失（真实流水线限制）**：C-A14"打印机
   换成兄弟的了"、C-A15"现在涂的是蓝色的"作为独立事件提取时缺先行
   语境，提取器合理地产出 0 候选（scripts/extraction-keyword-probe.js
   实测 keyword 存活 11/15）。需要提取时携带会话近期上下文（R-013
   候选主题）。
3. 其余为单发方差，且该失败模式在 3a/v3 同样存在（3/15 量级）。

### 8.4 结论

Phase 3c 的两项修复（提取预算 + 词法下限）在向量通道健康的条件下：
dedup 20%→95%，paraphrase 62%→79%，lexical 63%→93%，fact_recall
87.5%→95.8%，无任何机制指标回归。两个表面回归（precision_noise、
arbitration）经定向探针归因为评测判据缺陷与既有的无上下文提取限制，
不是 3c 引入的退化。后续工作：R-013（提取带会话上下文）+ 噪声指标
改造 + 干净环境 3a 配置对照（归因拆分，待算力预算决策）。
