# Phase 3c 实施计划：提取预算修复 + 词法下限 + decay（flag 门控）

> 依据：Phase 3a 统计基线（dedup 20%，量化后第一缺口）与 3b 库深归因
> （noise 残留 = BM25 词法通道）。基线 `930b628`。

## 1. 根因（dedup 20% 的真凶，与 R-012 假设不同）

隔离复现 + audit 链证明：dedup 失败**不是** AUDN 决策不稳定——
真模型探针 15/15 全对（改述 NOOP ×12、换值 UPDATE，温度下完全确定）。
真凶是 **MEMORY_EXTRACTION_TIMEOUT 级联**：

- 提取预算默认 2s（生产）/ 12s（评测），few-shot 后的 DeepSeek 提取
  经常超过它；
- 一条慢提取耗尽整个 drain 的预算 → 同批其他事件连带超时 → 目标事实
  根本没建出来 → 改述候选找不到可匹配的记忆 → 相似度 0 → ADD →
  「断言增长」被记为 dedup 失败。

修复：预算默认提到 30s（drain 是异步后台任务，不影响用户回合延迟）。

## 2. 词法相对下限（3b 归因的直接修复）

BM25 分数无上界，绝对阈值不可行；改为**相对下限**：低于词法通道最高分
30%（`MEMORY_LEXICAL_FLOOR_RATIO`）的长尾二元巧合在融合前丢弃。
默认 0.3 上生产；0 保持旧行为。

## 3. decay 重排（flag 门控，默认关）

- 实现：融合后按断言 updatedAt 做 14 天半衰期、权重 0.3 的 recency
  乘权重排（`MEMORY_DECAY_REWEIGHT`）；
- **默认关的理由**：3b 实测排序质量随库深零衰减（needle hit@1=100%
  @2000），decay 在当前数据下无收益空间；且系统没有按记忆的访问时间
  追踪，只有 updatedAt——等访问追踪落地后再评估开启。

## 4. 诚实负结果：AUDN 相似度短路被校准否决

原计划「cos ≥ 0.88 直接 NOOP 跳过模型」。校准（本地 bge-m3）：

| 对 | cos |
|---|---|
| 改述（A-D01 对） | 0.9193 |
| 改述（A-D12 对） | 0.9002 |
| **换值（榴莲→西瓜）** | **0.9092** |
| 严重度 UPDATE（B-15 对） | 0.7835 |
| 无关 | 0.4365 |

换值的相似度**高于部分改述**——相似度阈值无法区分两者，短路会静默
丢失换值更新（正是 R-011 事实级 key 要保护的场景）。方案放弃。

## 7. E-3 结果（2026-09-08，n=2/3）

### 7.0 两次假绿的教训（写入流程）

E-3 做了三轮才拿到有效数据，前两轮都被静默降级骗过：

1. 第一轮 15s 假绿：finally 里 `process.exit(0)` 吞异常 + shell USER 为空
   导致 PG 连接失败被包装成"0 失败"。修复：catch 打印 abortReason +
   非零退出；连接串显式解析 PG 用户（`070a735`）。
2. 第二轮 5 次跑（3 连跑 + 2 对照）全部在 Ollama 死亡（重启未自启）的
   纯词法退化模式下测量：paraphrase"回归"6.7pp、dedup"无改善"、
   floor/budget 两对照全持平——共享依赖（embedding 端点）死亡时所有
   对照一起失效。修复：embedding preflight，端点死直接 exit 2（`9268149`）。

### 7.2 归因与保留意见（诚实边界）

- **dedup 100% 与昨日 15/15 确定性审计探针一致**：预算修复让候选稳定
  入库，向量通道让相似度可用，审计器本身无缺陷。但 100% 完美到需要

  下测的；lexical +29pp 的改善幅度里有多少是 3c 修复、多少是环境恢复，
  需要在干净环境重测 3a 配置对照（budget12+floor0+向量存活）才能拆分。

  run3 在 C 组中断。第三跑与归因对照都等余额恢复后补。
- 归因拆分待办：dedup 提升在多大程度上属于预算修复 vs 向量通道恢复，
  需一次 budget12+floor0 的干净对照。
