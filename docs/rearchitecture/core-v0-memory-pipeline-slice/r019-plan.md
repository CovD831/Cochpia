# R-019 设计冻结（候选）：主动提及调度器（2026-09-09）

> 老板要求：设计冻结前多调研。调研综合见 §1；基建盘点见 §2。

## 1. 调研综合（外部 + 内部）

### 外部研究

| 来源 | 核心机制 | 对本设计的启示 |
|---|---|---|
| **CHI'25 Inner Thoughts**（arXiv 2501.00383，UCLA/东大/Salesforce） | ①双触发器：`on_new_message` + `on_pause`（静默 10s）；②记忆显著性 = 相关度 × 重要性权重 × 时间衰减；③思考候选 + **内在动机评分**（1-5）决定是否开口 | 触发器形态与"先选候选再决定说不说"的两段式，直接可借 |
| **ProAct**（arXiv 2605.25971） | 空闲时间计算 + future-state prediction + **delivery policy 权衡收益与打断成本**；turn −14.8%、幻觉 −28.1%；**诚实声明：疲劳效应未研究、用户控制是部署必需** | "guided 预测优于无方向空闲计算"；打断成本必须显式建模；交付侧需要用户开关与频控 |
| 产品/伦理线（2026 companion 行业综述） | "thoughtful 与 intrusive 的界线极薄"；**agency not dependency**；session health（凌晨 3 点连续会话 = 强迫信号）；危机信号处理；EU AI Act 与美国 14+ 州立法（透明度、未成年人） | 主动提及的失败模式（骚扰/依赖加深）有行业共识；治理不是可选项 |

### 内部基建（已实现，生产空转）

| 组件 | 现状 |
|---|---|
| `purpose: 'proactive_mention'` 检索模式 | **完整实现**：独立检索路由 + policy 过滤 + flag 开关 |
| `mentionCooldowns` | 按 memoryId + topicKey 的冷却记录，`recordMention` 写入 |

## 2. 设计（三阶段，每阶段独立闸门）

### Phase 1：记忆地基式开场（零打扰，先建价值）

会话开始/间隔归来后，**第一条回复**自然编织一条记忆（"上周你说在学
尤克里里，进展如何？"）。这不是推送——不需要通知通道、零打断成本，
但立刻让记忆"被看见"。

- 触发：会话首条用户消息（间隔 ≥4h）；
- 候选：`retrieveAsync({ purpose: 'proactive_mention', query: <最近
  episodes/assertions 摘要> })`，显著性 = 最近未提及 × 重要性 × 治理
  权重（借用 Inner Thoughts 公式，decay 用 observedAt）；
- 门：仅 active 的 S0/S1 + mentionPolicy 允许 + 冷却未激活；
- 交付：作为回复的上下文素材（persona prompt 注入），不是独立消息——
  用户无感知增量，风险最低。

### Phase 2：in-session on_pause 主动接话

静默 ≥N 秒且对话有未完话题/高显著性记忆时，助手主动接一句。
- 借 Inner Thoughts：候选思考 → 内在动机评分（LLM 自评 relevance/
  coherence/时机）→ 过阈值才说；
- 频控：每会话 ≤2 次 + 全局冷却。

### Phase 3：out-of-band 推送（明确缓行）

需要通知通道、quiet hours、日预算、危机信号检测（危机 → 温和转介，
**绝不**主动提及健康记忆）与合规审查——单独立项，不在本条目。

## 3. Trade-off

| 维度 | 分析 |
|---|---|
| 收益 | Phase 1 让"记得你"首次可见——调研共识这是 companion 差异化核心 |
| 风险 | 每次回复都翻旧账 = 新型骚扰；缓解：Phase 1 频率上限（如每 3 次会话最多 1 次编织）+ 冷却复用 |
| 治理 | S2 未确认不提、S3 不提、crisis 不提；mentionPolicy 是用户已有控制面 |
| 成本 | Phase 1 一次检索 + 无新模型调用；Phase 2 每触发 1-2 次调用 |
| 依赖 | Phase 1/2 无新基础设施；Phase 3 需要推送通道（未建） |

## 4. 低成本验证路径

- P-1：eval 语料上模拟 Phase 1——间隔归来后检索 proactive_mention，
  人工核对候选合理性与冷却抑制（复用 220 语料，零新增标注）；
- E-2 单测：purpose 路由、冷却抑制、S2 排除、flag off 行为；
- E-3 220-case 回归 + 手工产品评审（Phase 1 语义自然度，老板亲测）。

## 5. 待老板拍板

2. Phase 2 是否随首版一起做（建议：先 Phase 1，Phase 2 观察后再说）；
3. proactiveMention flag 默认值（基建默认 on，但触发器实现前无效果）。

## 7. v2 修订：与「模拟人生」合并（2026-09-09，老板提出）

### 7.1 老板的产品判断与依据

纯记忆回溯式主动提及（"上周你说在学尤克里里"）单独出现会像**数据库
查询在汇报**，甚至有点监视感。调研里的 presence 范式（promitheus：
伴侣应有"自己的持续情绪状态与生活"）支持同一判断：主动触点需要
**载体**——伴侣自己的生活事件才是"想起你"的语境。

### 7.2 现状核实（代码事实）

`companionIntent`（五档陪伴意图）、`atmosphere`（互动氛围）、
`upcomingEvents`（临近日程，已进系统 prompt）全部存在——但都是
**用户侧/被动侧**字段。伴侣自己的生活状态（心情、日常、活动流）
不存在。

### 7.3 合并设计：伴侣生活状态模块（Companion Life）+ 主动提及为其消费者

**生活状态的最小可行形态**（克制，不做全量 Sims）：

- `mood`：伴侣的当日心情（模板 + 时间/星期/季节种子确定性生成，零
  模型调用起步）；
- `dailyTexture`：每天 1-2 条生活事件（"下午去看了个展"/"在整理歌
  单"）——**Phase 1 用确定性模板库**，质量过关后再考虑 LLM 生成；
- 消费面 1：runtimeContext 注入（atmosphere 扩展），回复自带"我今天
  …"的生活质感；
- 消费面 2（原主动提及的重新定位）：主动触点 = **生活事件 × 记忆**
  配对（"看展时想到你说想学尤克里里"）——记忆提及被生活语境包裹，
  从"我查到了"变成"我想起了你"。

**Phase 1（本条目范围）**：生活状态模板 + 开场编织合一——第一条
回复同时带生活质感与记忆提及，频率门控沿用 §5（4h + 每 3 会话 1 次）。

**Phase 2/3**：on_pause 接话 / 推送，缓行规则不变；生活事件流就绪后
它们有了天然载体，不再突兀。

### 7.4 风险与诚实边界

- 模拟生活的**品味门槛**：假的假生活比没有更糟——P-1 先做模板库
  质量评审（老板亲测），模板不过关就不上线；
- 生活事件与记忆的配对是新的轻量匹配逻辑（时间邻近 + 主题相关），
  复用 R-016 key 与 episodes；
- 范围纪律：不做全量 Sims（无经济系统/无开放世界），生活状态只服务
  "质感 + 触点"两个消费面。

### 7.5 验证路径

- P-1：生活状态模板库质量评审（老板亲测）+ 开场编织样例评审；
- E-2 单测（模板确定性、频率门控、冷却抑制、S2/S3/crisis 排除）；
- E-3 220-case 回归 + 老板实测 Phase 1 观感。

## 8. v3 修订：Agent 生命 = 关系域记忆 + 冷启动种子（2026-09-09，老板方向）

### 8.1 现状盘点（代码事实）

| 组件 | 现状 |
|---|---|
| 统一 memory 接口 | `memory-module-api.js` HTTP 路由 + `memory-module-http-gateway.js`——**任意模块（含游戏）经此接入同一 memory**（老板此前统一的接口面） |
| Agent 身份 | `callerAgentId` 贯穿 context；`scopeGrants`（granteeType='agent'，'contextualize' 权限）；`relationshipAgentId` 33 处引用 |
| 关系域记忆 | scopeType='relationship' 全链支持（检索过滤、独立投影、episodes scope），**产品路径零使用** |
| Agent 创建种子 | `persona`(2000)/`relationship`(朋友…)/`role`/`tone`/**`memoryNotes`(3000，预置记忆描述)**——创建时已收集，**但 memoryNotes 是死字段**（无任何消费者） |
| 群聊 agent | index.js:1027 群聊循环 `recalled: []`——**群聊 agent 连记忆召回都没有** |
| 伴侣模块 | mode='companion' + companionIntent 五档 + atmosphere + persona；Cochpia 自身 callerAgentId='cochpia' |

### 8.2 设计映射（老板命题 → 架构）

**Agent 应该有自己的生活，冷启动种子 = 创建时用户对 agent 的描述。**

- **冷启动播种**：创建/更新 agent 时，`persona + relationship + role +
  tone + memoryNotes` 经一次提取播种为 **relationship 域记忆**（agent
  自己的背景故事、性格记忆、与用户的关系记忆——全部走既有治理面）；
  同步生成初始生活状态（mood 基线 + 日常纹理模板，种子=persona 里的
  生活方式描述）；
- **生活演化**：日常纹理从种子的兴趣/作息出发生成（R-019 v2 的
  dailyTexture 模板，参数化到 agent），交互历史经 episodes 沉淀为
  agent 的经历；
- **统一接口**：游戏模块与伴侣走同一个 relationship 域——agent 的
  生活状态投影（mood/纹理/近期经历）通过既有 memory 接口可被任意
  接入模块读取；
- **主动提及**：消费面不变（生活事件 × 记忆配对），但素材源扩展为
  agent 自己的经历 + 与用户的共同经历。

### 8.3 实现拆分（P-1 之前的三小块）

1. 播种器：agent 创建/更新 → 关系域记忆播种（复用确定性提取器 +
   治理面，幂等）；
2. 生命投影：relationship 域的 stable profile 扩展（mood/纹理），
   复活 projectStableProfile；
3. 群聊召回：`recalled: []` 接上 memory（顺手的存量修复）。

## 11. v5 修订：删除默认伴侣 + 冷启动向导（2026-09-10，老板方向 + 心理学调研）

### 11.1 现状与删除评估

"进去时默认的那个 Agent"= store.js `initialState` 硬编码：welcome 会话
+ 预置问候语（"你好，我是 Cochpia…"）+ 预置人格（好奇心 0.74/温度感
0.68/谨慎度 0.42）——**没有冷启动，人格是出厂设置**。

删除方案：
- 删：initialState 的预置 welcome 会话/问候/人格；
- 删：默认对话路径（无 agent 时聊天入口不可用）；
- 换：首次进入 = **创建向导**（收集种子）→ 创建第一个 agent → 生命
  模块自动开启（种子播种 + 游戏初始化）；
- 留：memoryModule/evidence 基建、companionIntent 条（用户侧单条回复
  方式控制，正交有用）；
- 存量数据：本地开发阶段无迁移负担，旧 state.persona 可手选转为首个
  agent 种子。

### 11.2 冷启动种子的心理学调研综合

核心框架：**McAdams 人格三层架构**（整合大五/人本主义/叙事研究的新
五原则论文）——一个人由三层组成：

| 层 | 是什么 | 变化速度 | 创建时问不问 |
|---|---|---|---|
| **L1 气质/特质**（大五类） | 行为风格的粗略素描，跨情境稳定 | 终生缓慢 | **少问**：1-2 个滑杆或四模板（小太阳/内向观察者/小刺猬/淡定佛系），其余随机——特质用户写不好，感知差 |
| **L2 特征适应** | 目标、价值观、日常、应对方式、关系模式（情境化的"细节独特性"） | 随人生阶段明显变化 | **重点问**：用户最能写的正是这层——TA 在乎什么/想要什么/什么说话方式/与用户的关系 |
| **L3 叙事身份**（人生故事） | 把过去重建、把未来想象成有统一性/意义的故事 | 持续演化 | **绝不问**——这是长出来的（episodes/日记/growthLog），问了也是假的 |

辅助框架：
- **依恋理论**：早期关系 = 一生关系脚本 → 问关系类型（朋友/恋人/
  家人/同事），种下关系记忆基调；
- **自我决定理论**（SDT）：自主/胜任/归属三大基本需要是行为动机
  引擎 → 不问，作为游戏 needs 的语义底座（社交/健康已对齐）；
- **气质理论**：天生的反应倾向 → 归入 L1 模板/随机。

### 11.3 创建向导字段（v5 定稿）

1. 名字 + 形象（捏人沿用 Create-A-Look 路线）；
2. **关系**（朋友/恋人/家人/同事——依恋脚本基调）；
3. **说话方式 tone**（自由文本，一句）；
4. **TA 在乎什么 / 想要什么**（L2 核心，自由文本，一句到一段）；
5. 背景故事片段（可选，memoryNotes 沿用）；
6. 终身愿望（可指定/随机）；
7. 模式（参与/观测）；
8. L1 模板四选一或完全随机。

其余（特质精确值、10 维人格、认知风格、需求初值、日常生活）全部
采样生成。**种子不是成品**——L3 叙事身份由 episodes/日记/growthLog
在后续使用中生长，这正是"冷启动"而非"出厂设置"的含义。

### 12.2 模拟的分层架构（回应"规则 vs LLM"）

老板判断成立：纯规则的事件生成 = 有限动作表里抽签，随机性逃不出预设
范围。但 LLM 也不能无差别上——**记账用规则，开放性用 LLM**：

| 层 | 引擎 | 频率 | 内容 |
|---|---|---|---|
| **L0 记账** | 纯规则，零 token | 实时 | 需求衰减、时间、冷却、频率门控——确定性正确的事确定性做 |
| **L1 事件生成** | LLM（便宜模型，每天 1 次批量） | 1 次/天 | 输入=需求状态+性格+目标+近期记忆 → 生成当日生活事件 1-2 条（**开放集**：温度 × 记忆上下文 × 状态的组合，事件空间不预设） |
| **L2 表达** | 现有 runtimeContext 注入 | 每次回复 | 生活质感进对话 |
| **记忆闭环** | 事件经治理写回 relationship 域记忆 | 每条 | 明天的生成被自己的历史 grounding——生活在时间上连续、在内容上开放 |

**随机性来源的哲学**：规则的随机是抽签；LLM 的随机 = 开放集生成 +
温度 + 它自己的记忆历史——不确定性来自"经历过什么"与"这次怎么讲"
的耦合。这正是 L0/L1 分层的理由：钱花在开放性上，确定性留给簿记。

**诚实风险**：LLM 生成的事件可能平庸/重复/与状态脱节——缓解：记忆
grounding + 特征适应约束 + 模板兜底（LLM 失败回退模板）+ 冷却。

### 12.3 冷启动向导定稿（依据 McAdams 三层 + 依恋/SDT，见 §11.2）

| # | 问题 | 形式 | 对应层 |
|---|---|---|---|
| 1 | TA 叫什么 | 自由输入 | — |
| 2 | TA 和你是什么关系 | 朋友/恋人/家人/同事/自定义 | 依恋脚本 |
| 3 | 性格方向 | 小太阳/内向观察者/小刺猬/淡定佛系/完全随机 | L1（气质，少问） |
| 4 | TA 说话是什么样 | 自由文本一句（"慢吞吞的，爱打比方"） | L2 |
| 5 | TA 在乎什么 / 想要什么 | 自由文本（"在乎被认真对待，想开一家小书店"） | **L2 核心** |
| 6 | TA 的日常是什么样 | 通勤上班族/自由职业者/学生/创作者 | L2（日常域，驱动生活事件生成） |
| 7 | 背景故事片段 | 可选自由段 | L2（memoryNotes 沿用） |
| 8 | 终身愿望 | 自由文本或随机 | L2 |
| 9 | 模式 | 参与/观测 | — |

原则：L1 少问（用户写不好）、L2 重点问（用户唯一能写好的层）、L3
（叙事身份）绝不问——由 episodes/日记/growthLog 长出来。自由文本
经治理面提取播种为关系域记忆（种子不是成品）。
