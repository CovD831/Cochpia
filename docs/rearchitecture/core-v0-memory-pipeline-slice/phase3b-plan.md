# Phase 3b 实施计划：bulk 合成语料 → 库深测量

> 依据：Phase 3 修订版——大数字只用于库深测量。decay 重排（3c）需要
> 「before」数字：当前实现在 500/1000/2000 断言库深下的检索精度与延迟。
> 基线 `b247a2c`。

## 1. 设计

- **合成语料**：2000 条断言 = 100 根「针」（needle，可唯一回答的事实，
  如「用户对 X 过敏」）+ 1900 条模板组合的干扰记忆（去重保证唯一）。
  全部走真实 API（recordEvent → createCandidate → promote）+ bge-m3 真实
  embedding 落 indexDocuments；构建期 persist 抑制，检查点一次性落库
  （全量快照 save 是 O(n)，逐条持久化会退化为 O(n²)）；
- **检查点**：500 / 1000 / 2000 三档库深，每档测量：
  - needle 查询 60 条（换述问法）→ hit@1 / hit@3 / hit@5、needle 排名分布；
  - noise 查询 20 条 → 召回条数（精度面）；
  - retrieveAsync 逐条延迟 → p50 / p95（含真实 embedding 调用）；
- **确定性**：固定种子 RNG，同种子结果可复现，供 3c 前后对比；
- 产出 `.rearchitecture-runs/phase3b-depth.json`。

## 2. 验收

- E-1 三个检查点全部完成，needle/noise/延迟三组数字齐；
- E-2 2000 深度下 p95 延迟与精度衰减曲线成立（无论好坏，如实记录）；
- E-3 同种子重跑数字一致。

## 3. 不在本片

- decay 重排实现与前后对比（3c，用本片数字验收）；
- 词法下限、AUDN 稳定性（3c）。

## 4. 实施结果（2026-09-07，seed=20260907，本地 bge-m3）

| 库深 | needle hit@1 | hit@5 | rank 中位 | noise 召回均值/查询 | p50 | p95 |
|---|---|---|---|---|---|---|
| 500 | 60/60 | 60/60 | 1 | 37.4 | 58ms | 68ms |
| 1000 | 60/60 | 60/60 | 1 | 37.4 | 59ms | 68ms |
| 2000 | 60/60 | 60/60 | 1 | 37.4 | 56ms | 72ms |

（证据：`.rearchitecture-runs/phase3b-depth.json`；调试输出确认 mode=hybrid_rrf）

## 5. 结论

1. **针尖检索在 2000 深度下零衰减**：hit@1=100%、rank 中位 1、p95 延迟
   平坦（56→72ms）——当前 hybrid 检索的排序质量不随库深退化，decay
   重排（3c）的「before」基线非常好，3c 的收益要在排序细分（浅语义簇
   内排序）里找，而不是全局精度；
2. **noise 召回在库深下饱和到 limit=50**：残留命中全部是 BM25 词法
   通道（「空气好不好」×「空气炸锅」级别的同域二元重叠），且合成干扰
   语料是同域日常闲聊——这与真实陪伴语料同分布，**结论外推有效**：
   词法通道在库深下主导融合结果，词法下限/RRF 权重（3c）是正确的
   修复位；
3. 构建侧修复了一个生成器死循环（组合空间 ~340 < 1900 导致去重
   while 无限循环），改为笛卡尔积保证唯一；embedding 并发 8 会触发
   本地 ollama 超时，降到 2 + 三次重试后稳定。
