# R-014 实施计划：上下文感知提取（设计冻结 2026-09-08）

> 依据：Phase 3c 归因（phase3c-plan.md 8.3、ledger R3C-005）——提取按
> 单事件无上下文进行，指代性换值消息（"打印机换成兄弟的了"、"现在涂的
> 是蓝色的"）缺先行语境，提取器合理产出 0 候选，arbitration 天花板
> ~80-87%。基线 `8fe414a`。

## 1. 设计

- 提取 prompt 增加会话近期上下文块：最近 N 轮（默认 4 条消息）的
  user/assistant 摘录，明确标注「以下是对话上下文，仅用于理解指代，
  不要从中提取事实」；
- **上下文在事件创建时快照**，写进 raw event（`context_snapshot` 字段），
  不在 drain 时回查——drain 是异步的，事件时点才是语义时点，快照保证
  幂等与重放确定性；
- flag 门控：`MEMORY_EXTRACT_CONTEXT_TURNS`（默认 0 = 关，行为与当前
  完全一致）；
- S2/S3 分类面不变（R-013 已扩到 sourceContent），上下文引入的多余
  候选由 AUDN 的 key 相同判定消化。

## 2. Trade-off

| 维度 | 分析 |
|---|---|
| 成本 | 每事件 prompt +~300-600 token；以 p50 3.3s、预算 30s 计，延迟有充足余量 |
| 隐私 | 上下文进入提取 prompt → 可能提取出前文事件的事实 → 与当前行为一致（同一会话的内容本就都会经过提取），治理路径（S2 pending/确认门）不变 |
| 重复风险 | 上下文中的旧事实被再次提取 → AUDN NOOP / 同 key 改述，不会重复入库（E-3 dedup 95% 已证） |
| 复杂度 | raw event schema 增一列（nullable），drain 无 schema 变更 |

## 3. 低成本验证路径（本次先做）

- **P-1 探针（15 次调用）**：extractor prompt 加上下文块，重跑 15 对
  换值的第二消息，keyword 存活从 11/15 → 目标 15/15；
- P-1 通过后再实施；E-2：flag off 单测行为不变；E-3：220-case 单跑
  arbitration ≥ 14/15 且 dedup/paraphrase 不回归。
