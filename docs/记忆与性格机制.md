# 记忆与性格机制（共生人生 · 地基）

> 本文档说明 Cochpia 已落地的「记忆形成」与「性格形成」两大系统的设计模式与代码运行方式。
> 它们是《共生人生》游戏方案中"规则引擎当大脑、LLM 当嘴"的地基：日常沉淀零成本，人格变化可审计、可回滚。
> 更新日期：2026-08-15

---

## 一、记忆模块：事件、断言、检索与治理

### 模式 1：自动沉淀（聊完自动判断要不要记）

不是每条消息都记，而是启发式判断"值不值得长期记住"。

代码：`server/auto-memory.js`

```js
// 是否值得沉淀为长期记忆
shouldRemember(text) {
  if (text.length < 12) return false;           // 太短不记
  const significant = /(记住|喜欢|讨厌|重要|承诺|约定|生日|想要|害怕|梦想|决定|计划)/.test(text);
  return text.length >= 40 || significant;      // 够长 或 含关键词
}

```

### 记忆模块的内部链路

代码边界：`server/memory-module.js`、`server/memory-module-api.js`、`server/memory-module-runtime.js`。

```text
聊天/外部调用
  → recordEvent（原始事件）
  → hold / createCandidate（记忆断言）
  → policy / confirmation（敏感性与权限治理）
  → retrieve / contextBundle（检索与上下文预算）
  → correct / revoke / forget（版本与删除）
```

Memory Module 是唯一记忆事实源。旧 `/api` 路径只作为兼容适配层，调用的仍是同一个模块，不再写入旧 `state.memories`。

### 对外接口

稳定接口由 `server/memory-module-sdk.js` 暴露，HTTP 路由由 `server/memory-module-api.js` 提供：

| 能力 | 接口 |
|------|------|
| 记录事件 | `POST /v1/events` |
| 创建/列出记忆 | `POST/GET /v1/memories` |
| 检索 | `POST /v1/retrieve` |
| 构建上下文 | `POST /v1/context-bundles` |
| 确认/修正/撤销 | `/v1/confirmations/*`、`/v1/memories/:id/*` |
| 忘记/删除 | `/v1/governance/*`、`DELETE /v1/memories/:id` |

`/v1` 是接口版本，不是模块名称；模块本身统一称为 Memory Module。

## 二、会话级对话设定

永久人格、人格版本、人格特质和成长驱动的人格变更目前全部停用。应用只保留会话级 Persona，用于临时指定当前会话的表达方式；它不会生成全局版本，也不会沉淀为永久特质。

---

## 三、完整运行链路（从聊天到人格变化）

```
用户发消息
   ↓
POST /api/chat/stream            (server/index.js)
   ↓
① Memory Module.contextBundle(消息内容) ← 检索、策略过滤、预算裁剪
   ↓
② buildRuntimeContext({            ← 组装 LLM 上下文 (server/runtime-context.js)
     messages,                     ← 最近 20 条（去掉被替代的）
     recalled,                     ← Memory Module 返回的记忆
     summary, persona,             ← 会话摘要、会话级设定
     upcomingEvents                ← 临近事件
   })
   ↓
③ LLM 流式回复（SSE：meta → text → done）
   ↓
④ 回复完成后自动沉淀：
   if (shouldRemember(用户消息)) {
     held = Memory Module.hold(...) ← 存一条记忆断言
     只形成受治理的记忆断言，不修改永久人格
   }
```

## 六、一句话总结

> **记忆**：聊天事件进入 Memory Module → 形成受治理的记忆断言 → 按策略检索并构建上下文。
> **对话设定**：当前只使用会话级 Persona；聊天不会生成永久人格、版本或特质。

---

## 七、给非技术同学的白话版

- **记忆**：像人会"记住重要的、忘掉不重要的"。聊天事件先进入 Memory Module，再经过敏感性、权限和确认策略，最后才进入可召回上下文。
- **性格**：Cochpia 不会"突然变"。每次聊天它只**悄悄写一条"成长小纸条"**（证据），你点了"确认采纳"，它才真的朝那个方向长一点，并且每次变化都留了"历史快照"，随时能退回之前的版本。
- **为什么这么设计**：防止 AI 人格被一次对话带偏，也让用户始终能"看得到、管得住"它的成长，符合产品"可验证成长"的定位。
